# ADR-0001：保留 Bash + systemd 技术边界

状态：accepted

## 背景

项目的学习目标是 Linux、systemd、系统采集、日志和服务生命周期。当前业务规模很小，迁移到 Python 或 Go 会增加运行时、打包和学习成本。

## 决策

企业版首期继续使用 Bash + systemd，并限制 Bash 只承担本机采集、配置、阈值判断和日志输出。

## 触发迁移评估的条件

- 引入网络 API 或远程协议。
- 引入持久化状态或复杂状态机。
- 引入并发调度或长期后台任务编排。
- 单脚本超过复杂度阈值且无法通过边界拆分解决。
- 测试隔离成本高于迁移成本。

## 结果

当前方案保持简单、可审查和可教学；未来迁移由真实复杂度触发，而不是预先模拟大型平台。
