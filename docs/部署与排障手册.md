# MiniOps Monitor 部署与排障手册

## 1. 项目简介

MiniOps Monitor 是一个只运行在单台 Ubuntu 主机上的资源监控服务。它每 60 秒读取系统已有的 `/proc`、`free` 和 `df` 信息，输出资源采样日志；当指标超过默认阈值时，额外输出 `ALERT` 告警。教学重点是理解 Systemd 如何托管服务、journal 如何保存日志，以及监控脚本如何把系统数据转成可查看的告警。

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Ubuntu 22.04.5 LTS |
| 资源 | 1 vCPU、1 GB 内存、至少 2 GB 可用磁盘 |
| 权限 | 可使用 `sudo` 的普通用户 |
| 网络 | 部署时可访问 Ubuntu apt 软件源和 GitHub |

脚本只识别 Ubuntu `22.04`。它不支持其他发行版、Docker、WSL 未启用 systemd 的环境或多主机部署。

### 架构说明

`miniops-monitor.service` 启动 Bash 脚本。脚本读取资源数据并写到标准输出，Systemd 把标准输出收集到 journald。学员通过 `systemctl` 观察服务状态，通过 `journalctl` 观察资源日志，`test.sh` 则把这些检查自动化。

服务不监听网络端口，不保存密码，也不向外部发送数据。安装阶段仅使用 apt 安装 `procps`，运行阶段只使用系统基础命令。

## 2. 分步部署

以下五条命令从全新 Ubuntu 22.04.5 虚拟机开始执行。复制命令时不要遗漏 `sudo`。

### 第 1 步：安装 Git

```bash
sudo apt-get update && sudo apt-get install -y git
```

预期输出示例：

```text
Hit:1 http://archive.ubuntu.com/ubuntu jammy InRelease
Reading package lists... Done
Setting up git (1:2.34.1-1ubuntu1.12) ...
```

解释：`apt-get update` 更新软件包索引；`apt-get install -y git` 安装下载课程项目所需的 Git，`-y` 表示自动确认安装。

### 第 2 步：下载项目

```bash
git clone https://github.com/hzd-git/miniops-monitor.git
```

预期输出示例：

```text
Cloning into 'miniops-monitor'...
remote: Enumerating objects: ...
Receiving objects: 100% (...), done.
```

解释：Git 将公开课程仓库下载到当前目录的 `miniops-monitor/` 文件夹。

### 第 3 步：进入项目目录

```bash
cd miniops-monitor
```

预期输出：此命令正常时没有输出；终端提示符所在目录会变为 `miniops-monitor`。

解释：后面的安装器和验证脚本都在这个目录中。

### 第 4 步：安装并启动服务

```bash
sudo ./install.sh
```

预期输出示例：

```text
[1/3] 安装依赖 procps...
[2/3] 安装监控脚本...
[3/3] 注册并启动 Systemd 服务...
Created symlink /etc/systemd/system/multi-user.target.wants/miniops-monitor.service ...
安装完成: 使用 sudo systemctl status miniops-monitor.service 查看状态。
```

解释：安装器会检查 Ubuntu 版本和 systemd，安装 `procps`，复制主脚本到 `/usr/local/lib/miniops-monitor/`，生成 Systemd unit，并设置服务开机自启。重复执行也会重载并重启服务。

### 第 5 步：运行自动验证

```bash
sudo ./test.sh
```

预期输出示例：

```text
PASS: 仓库仅包含 3 个脚本或配置文件
PASS: 三个 Bash 脚本语法正确
PASS: 非注释非空代码共 229 行，未超过 300 行
PASS: 监控脚本已安装
PASS: 服务已设置为开机自启
PASS: 服务重启成功
PASS: 服务正在运行
PASS: 资源采样日志已写入 journal
PASS: 告警输出链路正常
PASS: 全部检查通过。
```

解释：行数会随课程维护略有变化，但必须不超过 300。任意检查失败时，脚本继续执行其他可检查项，最后输出 `FAIL` 并返回非零状态码。

## 3. 功能验证

### 查看服务状态

```bash
sudo systemctl status miniops-monitor.service --no-pager
```

预期输出关键行：

```text
Loaded: loaded (/etc/systemd/system/miniops-monitor.service; enabled; ...)
Active: active (running)
```

`enabled` 表示开机自启已配置，`active (running)` 表示当前监控循环正在运行。

### 查看资源日志

```bash
sudo journalctl -u miniops-monitor.service -n 20 --no-pager
```

预期输出示例：

```text
... miniops-monitor[...]: 2026-08-14T... level=INFO event=resource_sample cpu_load_ratio=3 memory_used=28 disk_used=12
```

等到下一次采样或资源超过阈值时，可能还会看到：

```text
... miniops-monitor[...]: 2026-08-14T... level=ALERT event=threshold_exceeded resource=disk_used value=80 threshold=80
```

`cpu_load_ratio` 是 1 分钟负载除以 CPU 核数后得到的百分比，用来表示相对负载；它不是瞬时 CPU 使用率。内存指标基于可用内存，磁盘指标检查根分区 `/`。

### 默认告警阈值

| 指标 | 阈值 | 告警条件 |
| --- | --- | --- |
| CPU 每核负载比 | 90% | `cpu_load_ratio >= 90` |
| 内存使用率 | 85% | `memory_used >= 85` |
| 根分区使用率 | 80% | `disk_used >= 80` |

阈值写在主脚本中，教学默认值不要求学员编辑。`test.sh` 使用 `--self-test` 经过真实阈值判断函数验证告警格式，不会故意写满磁盘或制造高负载。

## 4. 常见故障排查

### 错误 1：提示“请使用 sudo”

原因：安装器需要写入 `/etc/systemd/system/`、安装 apt 软件包和管理服务。

```bash
sudo ./install.sh
```

预期输出：从 `[1/3] 安装依赖 procps...` 开始，而不是“请使用 sudo”。

### 错误 2：apt 无法下载软件包

原因：虚拟机没有网络，或 apt 软件源暂时不可访问。

```bash
getent hosts archive.ubuntu.com
```

预期输出示例：

```text
91.189.91.81    archive.ubuntu.com
```

若没有输出，说明 DNS 或网络连接异常；先检查虚拟机网络连接或 NAT 设置，网络恢复后重新执行第 1 步和第 4 步。

### 错误 3：提示“当前系统未以 systemd 作为 PID 1”

原因：当前环境可能是容器，或 WSL 没有启用 systemd，而不是标准 Ubuntu 虚拟机。

```bash
ps -p 1 -o comm=
```

预期输出：

```text
systemd
```

若输出不是 `systemd`，请在 Ubuntu 22.04.5 虚拟机中完成本课程，不要在不带 systemd 的环境运行。

### 错误 4：服务未运行或测试找不到日志

原因：服务启动失败，或刚启动时日志还没有写入 journal。

```bash
sudo journalctl -u miniops-monitor.service -n 30 --no-pager
```

预期输出：至少有一条 `level=INFO event=resource_sample`；若看到错误信息，先按错误提示修正后重新执行 `sudo ./install.sh`。`test.sh` 已最多等待 5 秒来避免日志启动竞态。

### 错误 5：测试提示脚本或配置文件数量不是 3

原因：项目目录内新增了 `.sh` 或 `.service` 文件，破坏了极简项目约束。

```bash
find . -type f \( -name '*.sh' -o -name '*.service' \)
```

预期输出：仅显示 `./install.sh`、`./test.sh` 和 `./src/miniops-monitor.sh`。删除额外的教学实验脚本，或将它们移出项目目录后重新执行测试。

## 5. 卸载和清理

以下命令只删除本项目安装的固定服务和脚本，不会清空系统的 journal 历史日志。

```bash
sudo systemctl disable --now miniops-monitor.service
```

预期输出示例：

```text
Removed /etc/systemd/system/multi-user.target.wants/miniops-monitor.service.
```

```bash
sudo rm -f /etc/systemd/system/miniops-monitor.service
```

预期输出：正常时没有输出。

```bash
sudo rm -rf /usr/local/lib/miniops-monitor
```

预期输出：正常时没有输出；仅删除 MiniOps Monitor 安装目录。

```bash
sudo systemctl daemon-reload
```

预期输出：正常时没有输出。Systemd 已重新读取服务配置。
